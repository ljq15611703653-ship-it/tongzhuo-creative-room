## 部署

1. 登录 GitHub 和 Supabase，创建 Supabase 项目。
2. 在新项目 SQL Editor 执行 `supabase.sql`。此文件用于首次部署，勿重复执行。
3. 执行 `002-invitations.sql`。生成两个随机邀请令牌，仅将 SHA-256 摘要及到期时间写入邀请表。
4. Authentication 保留注册开启、关闭邮件确认；数据库触发器限制有效邀请才能注册，自动创建姐姐或鼠鼠成员。邀请限用一次，初始有效期30天。私有令牌文件不得上传。
5. 在 `config.js` 填项目 URL 和 publishable / anon key。禁止填写 secret 或 service_role key。
6. Supabase Authentication 的 Site URL 设置成正式 GitHub Pages URL。
7. 当前仓库仅发布 index.html、app.js、style.css、config.js；Pages 使用 Deploy from a branch → main → /(root)。不上传私有邀请文件。
8. 分别用两个账户登录，验证下面的验收清单。

## 权限与产品规则

- 两人均可查看全部学习记录，只能增删改自己的记录、修改自己的昵称。
- 未登录及不在 members 表内的用户不可读取学习记录。
- 不允许用户自行增删成员或更改成员编号。
- 每人每天一条记录，同日再次保存为更新；允许补过去的记录，不允许未来日期。
- 日期按北京时间；今天尚未打卡时，连续天数计算到昨天。
- 每 15 秒拉取更新；同一账户同时编辑同一天采用最后一次成功保存的内容。
- 数据只在数据库保存成功后显示保存成功；失败保留表单供重试。

## 上线验收

1. A 打卡，B 最多 15 秒后能看到；刷新、退出再登录、换设备仍存在。
2. B 无法修改或删除 A 的记录，直接 API 请求也应被 RLS 拒绝。
3. 匿名请求不能获取 members/checkins；第三个非成员账户无权访问。
4. 同日更新不新增重复记录；补打卡正确更新连续天数；未来日期及无效时长被拒绝。
5. 网络断开时显示错误，未保存文本保留；恢复网络后可重试。
6. 导出包含双方全部记录。长期使用前建议设置独立备份。

## 陪你写（网页直接选 TXT）

姐姐登录进入陪你写，点“选择 TXT 并开始”，继续在原写作软件编辑并保存。Chrome / Edge 网页每 10 秒本机统计；保持页面打开、电脑唤醒。刷新后重新选择文件，同一浏览器同日可续计。首次接入保留云端已有的今日字数并从选文件时继续。

正文只在浏览器内存中按 64 KiB 分片处理，不上传、不落入 IndexedDB。文件名只在姐姐本机显示。IndexedDB 仅保存当前账号的文件句柄、日期及字数基线；云端请求只含日期、净增整数和鉴权信息。现有姐姐登录会话自动获取受限字数权限，无需用户生成或复制连接码。旧 exe / 插件无需继续使用。鼠鼠不能选择文件或写字数，仍只能控制小鼠与发送评论。

仍使用 003-writing-room.sql 的现有接口和权限，无数据库变更。local-counter.js 处理编码与计数，local-writer.js 负责本机基线和最小字数请求；app.js 已打包这些模块。两个网页不能同时监测同一账号，通过 Web Locks 阻止重复启动。暂停、关闭、退出登录会停止统计；休眠、后台节流会延迟更新。未保存到磁盘的文字无法计数，离线跨日无法追溯未观察的字数。网络错误和文件读取错误分别提示。

验证：node --test qa/local-writer.test.mjs qa/writing.test.mjs qa/mac-extension.test.mjs。真实 Mac 文件选择、两人实机同步仍需验收；不宣称已经实机验证。
